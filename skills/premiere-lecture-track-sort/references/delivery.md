# 交付与最终核验

每个序列独立交付：

1. 预览工程完整路径、来源项目摘要、来源快照、序列名称/UID、fps及实际PR版本。
2. config.json、review.json、plan.json、progress.json与最终audit记录；按每条分类生成用户能阅读的CSV或表格，列序列起止帧和时码、源片段、画面类、声音类、原轨/目标轨、证据、已实施/已正确/保留原因。
3. 已实施切点数和视频移轨数，V2/V3各多少；音频原轨原位、源覆盖无重漏、真实链接、字幕/标记/效果和其他序列核验结果。
4. 保留疑点的准确位置与原因；听审/机器分析/画面筛查各自覆盖范围；未检查属性或不支持结构明确列出。
5. 来源核对、抽帧、分类复核、执行和保存核验的实际耗时。执行器timing只覆盖队列调用，不能冒充全流程或纯网络耗时。记录等待和中断，不虚构耗时。

原生回读确认UID、媒体在线、序列可见与保存成功后，才能称“已在预览分轨并保存”。保存工程解析通过不是PR正常打开或声音正常的证明。read-only检查未覆盖的实时属性（如版本特有的声道/启用状态）补读或列为未验证。

不得把V2/V3称为删除清单。保留音画链接时，选/删视频可能连带音频。用户跨工程复制时，相关素材项也可能进入目标工程；不要指导用户连同引用素材箱一起删除。交付后结束，不自动进入清理停顿、删翻译、字幕合并或上传阶段。
