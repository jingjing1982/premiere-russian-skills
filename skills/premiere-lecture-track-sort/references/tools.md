# 可复用的分轨工具

## 能力与验证范围

- `scripts/track_sort.py build`：离线读取来源快照，核对基线链接，生成精确帧切分/移轨清单、期望状态和带工程/序列保护的原生脚本。不连接 PR，不建立或打开预览工程。
- `scripts/track_sort.py run`：经当前桥梁执行已准备的小操作；每步只返回受影响时间窗和轨道计数，运行开始、批末及恢复时全量读取；首个动作、首次必要切分及批末保存后运行链接核验。支持同一进程连续批次，省去重复启动核验。
- `scripts/prepare_preview.py`：离线核对一个或多个操作清单的校验值，生成主体只读检查、打开已有预览、激活目标序列、预览轨道/媒体检查的限定脚本和权限清单。不开 PR、不复制工程、不安装桥梁；使用兼容 ExtendScript 的写法，不依赖 `Array.indexOf`。准备后按本次实际桥梁机制核对所需能力；已有授权和许可足够时直接执行，不重复安装或询问。
- `scripts/saved_audit.py`：只读解析保存工程，核对 AV 覆盖与映射、音频轨道、真实链接、组件/关键帧图、字幕轨道图及格式、标记、其他序列。它不判断语音分类，也不证明媒体在线、PR 正常播放或声音自然。
- `scripts/test_track_sort.py`：纯离线回归测试，使用模拟客户端，不接触 PR。

底层方法来自 Windows / Premiere 2026、50fps 的实际分轨：QE `razor` 同步切音画、右侧子片段按对应范围重新链接、`moveToTrack(deltaVideo,0,"00:00:00:00",false)` 只移动视频。另有25fps演讲和问答预览的原生移轨与保存链接核验经验，未新增切点，因此不能作为25fps切分的实测证据。原方法做过历史保存工程核验；公开封装做过合成工程计划回放及模拟中断测试；不能冒称这版封装已在所有工程/PR版本执行验证。首次在新实际环境运行，只验证本次所需的一处动作：纯移轨只测试移轨，禁止为试验额外切分。规则已确认时由代理自行核验后继续。

工具当前支持：单速1x、25或50整数帧、每个视频恰有一个原轨音频链接、各视频之间及各音频之间不重叠、标准文件素材。50fps切分与移轨、25fps移轨有实际工程验证；25fps切分尚需在实际需要切分的预览中验证。转场、变速、叠层、多机位、嵌套、拆分多声道或非帧对齐音频不自动简化。整序列存在不支持结构时该执行器不能运行；保留内容和分类表，选择另经验证的原生方法；不要改输入来伪装满足条件。

## 配置与离线准备

先保存授权范围内的来源快照，并记录实时基线，独立预览应以该快照制作、在 PR 打开并确认 UID/轨道。track_sort和prepare_preview不会替用户保存主工程或创建工程副本；副本由task_setup.prepare提前建立。配置 JSON 的路径都用绝对路径；轨道索引从0起，视频 kind=0、音频 kind=1。

```json
{
  "main_project": "D:\\Projects\\lecture.prproj",
  "source_snapshot": "D:\\Task\\source.prproj",
  "preview": "D:\\Task\\lecture-preview.prproj",
  "uid": "本次真实序列UID",
  "fps": 50,
  "tpf": 5080320000,
  "review": "D:\\Task\\review.json",
  "cuts": [
    {"frame": 71088, "video_track": 0, "audio_track": 0}
  ],
  "moves": [
    {"start": 70852, "end": 71088, "video_track": 0, "audio_track": 0, "target_track": 2}
  ]
}
```

数字仅示意格式，必须替换为本次已复核时间。`baseline` 可选，为完整 AV 行数组 `[kind,track,start,end,source_in,source_out,media_path]`，全部时间为整数帧；提供时必须与来源快照一致。

公开版额外强制读取review.json：全片覆盖、来源摘要、观众优先、翻译音频证据、每个切点依据与动作一一对应。格式见 [operation.md](operation.md)。原作者的历史授权不适用于新用户。生成清单前须已有可读的独立预览，且与执行基线一致；可先用task_setup.py制作。首轮分析完成后再build，不能把模板中未审核的条目当作审核完成。没有动作也生成零动作清单及分类摘要。

`cuts` 按给定顺序执行，必须严格位于当前片段内部；重复切点拒绝。`moves` 在所有切分后执行，只允许移到V2或V3，目标占用拒绝。人工已正确分轨的片段不列入动作。每个操作都保留分类理由和证据层级的伴随清单，不能让工具根据目标轨道自行推断声音类别。

```powershell
python -X utf8 <skill>/scripts/track_sort.py build <config.json> <全新清单目录>
```

输出包含 `baseline.prproj`、`plan.json` 和限定副本路径/UID/timebase的 `.jsx`；现有目录不会覆盖。检查操作数量、窗口、目标轨道和最终期望状态后，再进入实际已授权执行。

纯观众且已有切分时，`cuts` 留空，`moves` 只包含确定观众且尚未在V2的片段。不要为了满足示例配置而切分或加入V3动作。

统一生成本次接入请求（可一次传入演讲、问答两份清单）：

```powershell
python -X utf8 <skill>/scripts/prepare_preview.py <演讲清单目录> <问答清单目录> --out <全新接入目录>
```

`manifest.json` 包含限定路径、UID、操作类别、脚本及清单校验值。安装时只开放列出的具体请求和原操作清单，不把清单解释为任意脚本执行许可。源读取不要求激活源序列；预览读取和操作必须核对正确活动序列。预览工程必须已经按冻结来源建立。打开/激活失败即停止，不继续向其他工程发操作。运行前检查当前 PR 版本是否支持生成脚本所用方法；新准备脚本只通过离线模拟验证，不能称为已经实机验证。

## 通过已配置桥梁执行

`--adapter` 指向本机已经配置、已检查的 Python 客户端文件，须提供 `run_pr_script(script)` 并返回原生脚本 JSON 对象或 JSON 字符串。桥梁许可仍按实际项目核实。客户端未建立或脚本被拒绝时，工具报错并停止，不会自动修改桥梁、签名扩展、扩大白名单或换通道。

```powershell
python -X utf8 <skill>/scripts/track_sort.py run <清单目录> --adapter <已配置客户端.py> --limit 20 --until-complete --execute-preview
```

`--execute-preview` 是防止误把离线校验当成执行的命令开关，不是要求再向用户索取相同授权。所有实际脚本限定到预览工程和指定序列；不支持把主体路径当预览路径运行。先测试一处操作，再连续完成其余清单，不要每批结束都让用户回复“继续”。

`--limit` 是每批操作数，`--until-complete` 在同一进程内连续完成后续批次，每批仍保存并全量核验；不传该参数则只完成一批。首次动作的保存核验内置在执行器中，无需为了试运行反复启动。任何错误停止队列，不自动重试；需要用户介入或预期会断线时停止后按恢复流程重读。禁止并发写同一预览、同一进度目录。

每次运行写一份 `timing-*.json`，包含实际全量读取、动作及局部核验、保存、已保存文件核验的调用次数与耗时、总耗时及完成/失败状态。调用耗时包含其中的等待，未独立测量网络时间；不把这些数据当成全流程识别耗时或用户听审时间。

必须先确保预览现状与基线一致、目标轨道存在、轨道可操作、没有用户并发编辑。阶段每步进行局部检查和全轨计数；首处切分、批次结束时全检并保存，读取真实链接和字幕结构。工具没有完整枚举的实时属性（例如独立声道设置、启用状态或版本特有属性）仍由代理按基线补查。

## 中断恢复

`progress.json` 原子记录已完成前缀及保存核验进度。再次执行同一命令时先读完整实际状态：

- 与已完成前缀一致：从下一项继续。
- 恰比日志多完成一项：可能是动作完成但响应/记录丢失，核验并保存后接续，不重做。
- 位于半次切分、状态不对应任何前缀或跳过多项：停止该队列，提供具体差异；禁止盲目重复、覆盖用户修改或自动回滚。

工具恢复读取会保存已确认属于该清单完成前缀的独立预览，以读取实际链接后再继续；不保存主工程。恢复记录缺失而预览已有改动时不猜测进度。清单或脚本变动后不得沿用旧日志，应重新核对并准备新清单。

## 校验工具本身

```powershell
python -X utf8 <skill>/scripts/test_track_sort.py
```

离线通过只能证明所测计划与恢复逻辑，不等于当前项目已分轨，也不代替真实音频检查。制作、保存与声音复核的结果分开交付。
