The application title, a same-named sequence, or a previously opened preview alone is insufficient when multiple projects are open; use the sequence's Reveal in Project action if necessary. A skill grants no permission to edit a protected project. Back up the authorized project before changing captions, preserving the original sequence and caption track in that backup. Never change shared source media or present an older preview as the current source.

## Russian layout

Audit every cue's actual rendered lines, including existing explicit breaks. **Prefer one Russian line whenever the full sentence fits within the measured caption width.** Only when it does not fit, use at most two Russian lines. This is an absolute maximum: no title exception permits a third Russian line. First protect complete scripture, treatise and general book titles as described below; then, among title-safe boundaries, apply the user's visual preference in this order:

1. Start with the final **three words** on the second line. Standalone punctuation such as an em dash is not a word. The first line **must be strictly wider** than the second in rendered width; equal-width rows also fail. Do not try to balance the rows.
2. If three words make the lower line close to the upper line in measured width, try **two words**, provided both lines fit and the first remains longer. The script uses a lower/upper width ratio of 0.80 as a reviewable approximation of “close”; this is an implementation threshold, not a user-specified physical limit. Also try two if three would make the lower line longer. Never leave only one word below.
3. If the first line cannot fit with three words below, move additional words down, taking the smallest fitting tail of four or more words. Do not move extra words merely to keep an ordinary clause or phrase together; complete scripture, treatise and general book titles are the mandatory exception below. If no acceptable two-line split fits, check the long-scripture-title exception below; otherwise flag the cue for manual width adjustment. Never shrink the font.

For example, prefer `Мне кажется, бедствия берут начало в трёх` / `ядах человеческого ума.` and `Большое спасибо кхенпо Содаргье за глубокое` / `объяснение темы бедствий.`. Ordinary semantic heuristics may identify a boundary for review, but must not override this three-word-first visual rule or reinstate old manual overrides that do so. Title protection for scriptures, treatises and general books is an explicit exception, not an optional heuristic. Check adjacent cues for avoidable swings between balanced rows and very short tails, without forcing different sentences to have identical physical widths. Preserve all Russian and Chinese words, punctuation, order, cue numbers and Chinese line breaks. Do not shorten or retranslate text to make it fit.

### Title protection and the long-scripture-title exception

- **Scope: all scripture titles, treatise titles and general book titles (经名、论典名、普通书名) receive the same mandatory protection.** A complete title must normally occupy one actual rendered line, including its enclosing quotation marks when present; only the explicit long-scripture-title exception below permits an internal break. This applies to religious and non-religious books alike; do not limit protection to titles containing words such as «сутра» or to the examples below.
- Before choosing breaks, identify the complete Russian titles of scriptures, treatises and general books in each cue from the Russian wording, quotation marks and the corresponding Chinese titles such as `《六祖坛经》` and `《金刚经》`. For example, protect all of `«Сутра Помоста Шестого патриарха»` and all of `«Алмазная сутра»` separately. Preserve the source's actual spelling, case and punctuation; these examples are not replacement translations. An unquoted title also needs protection when identifiable; not every quoted phrase is a title. Uncertain title boundaries must be flagged for review.
- Treat each identified title, including its enclosing quotation marks when present, as one indivisible layout unit. Do not insert a break inside it unless the long-scripture-title exception below applies. Inspect existing explicit breaks too: normally join a break inside a title with an ordinary space and choose a permitted break outside the title; retain or select an internal break only when the exception below is needed to keep the whole Russian cue within two lines. Do not use NBSP substitution or other text changes to force this result.
- Prefer moving the whole title onto one row. Outside that exception, each title must remain intact; multiple titles need not share the same row. Title integrity takes priority over the three-word/two-word tail preference and the preference for a strictly wider first line. First try title-safe splits that also meet those preferences; if none do, use a title-safe two-line split that fits the measured width, even if the row proportions differ. The long-scripture-title exception relaxes title integrity only; the two-Russian-line limit never changes. Do not modify Chinese line breaks.
- **Authorized long-scripture-title exception (超长经名例外):** first try keeping the complete scripture title on either the first or second line. If preserving it as an indivisible unit prevents the whole Russian cue from fitting in two lines (for example, placing the whole long title on line two would cause a third line), the user permits a break inside that title BETWEEN LINE ONE AND LINE TWO. Use available space on line one for the beginning of the title and continue it on line two, at a natural word or phrase boundary. Never split a word or detach punctuation. This exception relaxes title integrity and row-proportion preferences only to keep the complete Russian cue within the unchanged two-line maximum; it never authorizes three lines. If a title-safe two-line layout fits, use it instead. Ordinary book and treatise titles retain the existing protection. Preserve all wording, styles, Chinese layout and exact timing. If no two-line layout fits even after the permitted internal title break, preserve the source layout and report it as unresolved; an existing three-line display is a reported problem, not an accepted result. Do not shorten text, shrink fonts, resize the box or alter timing.
- If a title alone exceeds the existing width, or the full cue cannot fit in at most two title-safe rows, first check the long-scripture-title exception. If it does not apply or no permitted layout fits, preserve that cue's source layout and mark it as unresolved. Do not silently split a title as a fallback, abbreviate/retranslate it, change font/size/tracking/box geometry, move words to another cue or alter timing. A title already split across distinct timed cues also requires a reported exception; do not merge or retime those cues. Only the user can authorize a different remedy.
- The packaged `layout_titles.py` enforces independently reviewed title spans from the input manifest. It preserves unreviewed cues and reports them. Calculated fit never replaces actual Premiere rendering validation.
- Verify every affected title in the actual Premiere-rendered result: absence of an explicit newline does not prevent automatic wrapping. Classify each as `verified_same_line`, `verified_long_scripture_wrap`, `unresolved` or `unverified`. Use `verified_long_scripture_wrap` only when the authorized exception and every actual rendered line have been checked, including the absolute two-Russian-line limit and vertical fit alongside the unchanged Chinese lines. If actual rendering cannot be checked, report it as unverified rather than promising it fits. Report any Chinese title visibly broken too, without changing Chinese layout under this Russian-only skill.
- **Mandatory handoff reminder:** list every unresolved or unverified title with cue number, original start/end, exact title, reason (for example too wide, no valid two-line layout, uncertain title boundary or Premiere rendering not checked) and what the user needs to inspect or adjust. State this in the final response, not only in an attached report. For a long list, give the total and representative locations plus a complete linked list. Also list every applied long-scripture-title exception with cue number, start/end, exact title and final Russian line count; distinguish these authorized wraps from unresolved failures. Say all titles stay on one line only when every identified title was actually verified on one line and no wrapping exception was used.

The user handles the flymark/logo clearance and caption box placement manually in Premiere. Do not use the flymark as an automatic line-break constraint or change its position. Do not shrink subtitle fonts. If two Russian lines cannot fit within the measured caption width, check the long-scripture-title exception; if it does not apply or still does not fit, flag the cue for the user's manual box-width adjustment.

## Width measurement and calibration

Measure the exact Russian substrings, including every original space and punctuation mark. Word count is a separate decision: standalone punctuation contributes width, not a word. Never collapse repeated spaces, convert NBSP/narrow NBSP, normalize Unicode, or reconstruct the text from a word list for measurement. Replace only a permitted ordinary space with a line break; preserve all other characters. An existing Russian layout break may become one ordinary space. Keep Chinese line breaks unchanged.

Inventory **each cue's** font family/file/face, size, tracking, horizontal scale and effective text-box width, including local overrides and mixed character styling. Group only cues proven to share these properties. A cue-level narrow box must never inherit the track-wide width. Unknown properties remain unknown; flag the affected cues rather than claiming all styles are identical from one font name or a common payload suffix. Read-only project extraction may aid the inventory, but undocumented fields require visual validation before interpreting their units.

Calibrate each relevant profile against current Premiere rendering: include fitting single lines, automatic wraps, punctuation/space-rich cases and longest proposed lines. Inspect the actual text-box outline as well as the text. A shorter predicted line wrapping while a longer one fits invalidates a shared profile; resolve geometry/style/source differences before changing thresholds. Never solve this by globally lowering width and needlessly splitting fitting captions. Width evidence is scoped to the source project/sequence, source hash, font version and profile; invalidate it when these change.

Use `../scripts/layout_titles.py` with the exact per-cue manifest in [layout-manifest.md](layout-manifest.md). Measure every profile using the real font file, size, tracking and horizontal scale; retain unknown profiles unchanged. Every cue requires a reviewed Russian/Chinese boundary, title list (empty only after review), calibrated width and evidence reference. This replaces the old character-count and generic reflow entrypoint.

The JSON report keeps all PR visual statuses unverified. Inspect explicit breaks and automatic wraps in Premiere. Review all title exceptions and near-limit cases; disclose any uninspected ordinary cues. A rendered review export can be sampled inside each cue, but OCR triage alone is not visual acceptance. Never claim whole-project visual verification from a few samples.

The user sets caption fonts and sizes in Premiere. This skill must not set, normalize, substitute or batch-change the font family, face, size or other typographic style attributes. Before calculating line widths, read the font and size actually present on the target captions; if the user changes them, recalculate and recheck the layout. Do not assume the earlier Microsoft YaHei 48 test still describes the current track. Avoid SRT reimport when it would discard styles or shift times; prefer a verified narrow edit. A font shown for the whole cue may lack Chinese glyphs and trigger fallback, so inspect Chinese visually when validating the result.

Match the actual installed font family, face and file. Do not substitute a similarly named font or infer widths from a monospace label. Recalibrate after font/style changes.

Check that the installed Premiere bridge can actually read and edit caption text before planning a batch change through it; a generic script entry point does not imply caption-track support. If it cannot, check whether supported UI editing and readback can satisfy the same invariants. If neither can, follow the operating-mode limitation above; use the authorized preview workflow when requested or invoked without a narrower inspection-only restriction. Never patch the open source project file or silently replace its caption track. When captions share internal text data, edit only the intended cue and verify that no other cue changed; leave a cue for separate review if this cannot be established.

Before saving a project, check for Premiere's missing-font warning. Identify whether a missing font belongs to a caption or another graphic; do not save after silent substitution and present the result as a style-preserving edit. Report font problems to the user for manual correction.

## Timing audit only — never repair

All cue starts and ends are immutable in every run of this skill, including a full subtitle-reflow run. Audit consecutive cues on the selected caption track using their actual end and next start. Report positive gaps of **up to 2.000 seconds** as unclosed gaps for the user to review; **more than 2.000 seconds** is allowed and must be distinguished from problems. An exact zero gap is closed. Report overlaps separately without changing them. Never extend the preceding end, move the next start, snap to a frame, merge cues or invoke another tool to repair timing. This replaces the earlier automatic closure rule. The public layout helper has no timing-repair option; requests to repair times are a different task.

For an authorized reflow output, the layout helper writes the `gaps` array in its JSON report with both cue numbers, gap milliseconds and classification; retain the original cue times to locate each gap. Summarize the number of unclosed gaps and give their locations directly in the response; link the full list when it is long. If there are none, say so. Use exact original Premiere ticks for a project audit and include sequence-frame timecodes and frame rate; for an SRT-only audit, label the times as milliseconds and do not invent frame accuracy. Preserve track identity and sequence timecode origin in project reports.

SRT uses milliseconds; Premiere aligns captions to frames. Matching SRT strings does not prove the Premiere timeline stayed fixed. In either operating mode preserve exact source ticks. Direct edits as well as any authorized import or transfer require reading back **every** cue count/start/end against the pre-edit ticks. A frame shift, extra short fragment or missing cue is a failed handoff, not an acceptable rounding difference. Report the failure and do not deliver it as verified or automatically retime the destination. Do not reuse historical gap-closing or retiming scripts in this workflow.

## Verification and handoff

For every run, maintain a one-to-one mapping to the restored source cues. Reject any output with a different cue count, added fragment, missing cue, changed start/end tick or changed non-layout text. Check adjacent identical text without automatically deleting it: repeated speech can be genuine. Compare against the latest restored source, not a previous preview that may already contain paste fragments. The helper requires new, distinct paths for the output and all reports, protects its input paths, and refuses existing destinations.

In preview mode, give the preview project and its target sequence clearly distinct names and verify ownership after opening. Retain the source-file hash and verify it is unchanged before handoff. In direct-edit mode, retain the original project and sequence identity, record the recovery backup path and hash, and compare the edited project's contents against the pre-edit baseline; the working file hash is expected to change after saving. A review export must come from the identified target sequence, and its frame checks must map to source cue times.

When transferring captions back, do not recommend an overwrite paste onto a populated caption track. A time offset can leave short old fragments and duplicate captions even when the preview itself is correct. Within the user's authorized scope, back up first, replace only the intended caption track's contents, paste at the exact original first cue start, and read back every cue count/start/end against the preview. Do not use the current playhead or a rounded seconds value as the intended start. If the user will do the transfer, provide these checks and distinguish an audited preview from an unverified destination; do not claim the main project is fixed before the transfer is checked.

After an authorized backup, inspect representative captions and all flagged exceptions in the rendered Premiere sequence. Compare before/after project state for cue count, text, starts, ends, font families and sizes, text-box geometry, bins, sequences, and the untouched audio/video tracks and media references. Keep the original caption track and sequence available in the recovery backup. Report separately: operating mode, exact edited project/sequence and saved or unsaved state; backup path (or preview path); line-break changes; zero timing changes verified or verification still outstanding; unclosed gap locations; any authorized Premiere transfer and its verified scope; the user-set font and size observed for measurement; and the actual visual and frame-accurate checks. Do not claim uninspected captions are visually correct. Cross-project transfers can bring dependencies into the destination; an unexpected bin, sequence or media item must be reported, not silently accepted or deleted.
