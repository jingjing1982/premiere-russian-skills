# 无交替翻译：按说话轮次、少切口合并

当用户说“没有翻译”，先区分**视频中没有交替口译**与**字幕尚未翻成俄文**。本模式需要已有俄中双语字幕；没有口译不等于没有俄文，也不代表可以把所有人合并。相邻字幕可能仍有掌声、笑声或自然停顿，本模式不把这些正间隙自动当作大段边界。

## 大段和小段

- 先据字幕话语关系、讲话音频/画面核对说话轮次。主持人、致辞者、上师、每位提问者分别划开；同一位提问者追问与上师短答也分别划开。镜头切到听众不等于换人；引述“你说我”等对白不等于真正换人。记录证据层级及不确定的短句。
- 若短句如“好/对/谢谢”说话人无法判定，单独保留这条为待核查轮次，不把它猜进另一人的长段。不能自动删去。
- 轮次内只按完整句意和90秒上限拆分，优先最少小段，不按每个红点切。每条同时检查源时间跨度与计算时长≤90秒，不能只检查其一。只分配整cue；过长完整句需要在cue边界拆开时明确报告，不改句。
- 同样最少段数的方案，优先完整句界、避免拆开经名/书名/引文、避免不必要的极短尾段；可比较原有必要切口处的接缝，但不能增加段数来掩盖锚点误差。最少SRT条数不等于对所有视频剪辑方案都达到全局最少切刀。

## 本用户确认的优先级（2026-11-17更新）

本用户版默认：**整份SRT不得重叠；每小段首个红点保持定位，必要时整体移动无锚点段。** 这覆盖旧“允许重叠只报告”规则；正空隙仅在换人交接或两侧固定锚点确实不能兼顾时保留；不能把可消除的同轮次空隙也当作允许保留。固定锚点与无重叠无法兼顾时，仅报告容量缺口并等待取舍，不导出重叠SRT。

1. 每个小段若有红点，选择按红点时刻排序的第一个；按其俄语对应词/短语计算起点，按帧网格舍入，记录舍入误差。后续红点照样保留映射并报告偏差，不取平均起点、不增加切口、不改语速。
2. 只有结尾合十致谢一个锚点时，从“谢谢/感谢”对应俄语位置向前倒排，不强制从原开头开始。确认这是谢词开始还是结束，不能机械把红点当整段终点。若俄文是完整感谢句而不是单词Спасибо，可按整句语义收束的词尾对齐并注明依据，不添加Спасибо。
3. 无锚点小段优先与同轮次相邻小段相接：首个锚点以前向前倒排；首个锚点以后向后接排，遇下一个有锚点的小段保留它的独立位置。**整个轮次无红点时，默认以该轮次最后一条源cue的结束为尾界，按总计算时长向前倒排。** 不再默认从原首cue开始而在同一人讲话的尾部留下余量；尽量把余量集中在轮次交接前部。因90秒拆成多条时各条仍首尾相接，SRT分条本身不要求视频切一刀。
4. 每轮边界和同轮次内部均检查无重叠。首锚组固定，无锚点组保持时长整体排开；允许不同人的字幕首尾相接，不合并文字。调度先前向避免前段占用，再在下一固定组/视频尾界之前倒排可移动段。若两个固定边界之间的可用时间小于全部待排时长，则停止导出，报告缺口；不得缩时、提速或挪首锚。
5. 负起点或任何输出重叠不生成SRT，不能用“核对稿”放行。移动无锚段后跨说话人源画面边界、源异常或次锚偏差超2秒时交明确“核对稿”，列出需要人工匹配的镜头；不能标成已实现音画同步。源字幕小间隙不是错误；同轮次可移动组之间不得人为留空；固定锚点之间不可消除的余量集中在一处并报告，不散成多个空隙。

## 工具

两种合并模式都必须提供`speaker_review`。先完成音视频/用户确认的独立归属，再填写计划，不凭字幕词义或最终分组伪造证据。`speaker_guard.cue_fingerprint(cues)`计算绑定源cue编号、时间和中俄文字的摘要；任一变化后重新核对。结构：

```json
{
  "speaker_review": {
    "cue_sha256": "由当前源cues计算的SHA256",
    "evidence": [
      {"id": "ev1", "kind": "audio_review", "reference": "实际来源路径及核查起止时间", "observation": "实际听到的讲话者及交接台词"}
    ],
    "attribution": [
      {"cue_id": 1, "turn_id": "turn1", "status": "confirmed", "evidence_id": "ev1"},
      {"cue_id": 2, "turn_id": "turn2", "status": "confirmed", "evidence_id": "ev1"}
    ],
    "boundaries": [
      {"before_cue": 1, "after_cue": 2, "translation_status": "separable", "evidence_id": "ev1"}
    ]
  }
}
```

`kind`支持`audio_review`（实际听审）、`visual_dialogue_review`（画面与台词联合核查）、`user_confirmation`（用户明确确认）。文字猜测和机器标签不能填成这些证据。引用应具体到文件/片段和时间，或可定位的用户确认内容。连续讲话可共用证据记录，无需每条重复听审，但每个可疑交接点必须检查。

`attribution`按原顺序逐条覆盖，轮次ID须与`turns`一致且连续。`boundaries`覆盖每个轮次交接；`separable`表示已核实能按原cue分开而不改字。未决或混入两人的cue仍保留在原文件和问题记录中，不得伪装confirmed让程序通过。跨人的俄语整句不得靠合并解决；需要重新翻译或拆cue时，另行说明必要变更并取得授权。

`scripts/speaker_timing.py plan.json output_directory` 使用标准库，引用 `gesture_timing.py` 的音节计数与时间格式函数。它不负责识别说话人、理解手势或翻译。

输入沿用`speed,grid_ms,video_end_ms,source,cues,anchors`。每条cue包含`id,start_ms,end_ms,ru,zh`，可有`readings`。新增必填：

- `mode: "speaker_first_anchor"`，固定该用户已选策略。
- `turns:[{id,speaker,cue_ids:[...],evidence:...}]`，各轮次按顺序覆盖所有cue且每条一次。
- 可选`groups:[{turn_id,cue_ids:[...]}]`：人工审阅后的分组。省略时工具按90秒及句尾标点选最少条数，输出后须语义复核，不能把标点检测称为理解了完整句意。
- 可选`forbidden_cut_after:[cue_id,...]`：语义审阅认定不应拆开的句间边界。比如“会发现以下情况。”与随后解释，不能仅因句号就机械拆开；重新规划时仍优先最少段数，不修改文字。
- `anchors`继续使用精确`cue_id,char_offset,target_ru,time_ms,evidence`；可补`target_zh,alignment_basis`。本模式不用扩展窗口偷偷变动首锚。所有原红点应在映射中出现一次，已获准忽略的另记原因。

输出合并双语SRT、计算核对JSON和中文定位报告。逐条从原cue拼接并回读核验文字、顺序、编号、时间与≤90秒；报告轮次、首锚、次锚、替代起止、全部接缝与来源覆盖。自带逐字符校验不替代输入源文字映射的独立核查。

## 手动处理提示

移动整条字幕会一起移动这条里的所有预计发音位置，不能通过只拉长结束点来修正内部词时差；已经生成的视频要用实际音频词时刻复核。报告对每个次锚给出单独对准该点的替代起止、整段移动量和会失去原首锚对齐的提示。诊断中的正值为空隙、负值为重叠；交付SRT只允许非负接缝。无锚段整体移动由技能完成并报告，涉及首锚取舍才询问；不在PR自动剪切。

## 导出硬检查与移动记录

`nonoverlap.schedule`在首锚定位后处理可移动组，返回`timing_adjustments`（原起止、新起止、移动量、原因）；所有红点偏差必须在最终排布之后重算。固定边界容量不足抛出含缺口的错误，调用者保存诊断并说明取舍，不能跳过检查继续导出。两模式导出前及SRT回读后均执行全局无重叠检查。每组文字、时长和来源归属仍必须独立核验。

用户针对具体冲突明确同意放宽首锚时，计划可加`approved_anchor_shifts:[{anchor_id,shift_ms,authorization}]`：只接受当前首锚ID、帧网格整数移动量及本次确认记录。该字段移动合并段，不修改原红点时刻；后续无锚段按该轮次接排，再执行全局无重叠检查。报告必须列出获准偏移和最终预计误差，不可仍称首锚精确对齐；本次许可不能自动沿用到别的锚点或项目。

## 少切口的实际验收

- “尽量少分组”与“尽量少后期刀口”是两项检查。即使只有一条SRT，也要核对整个说话轮次前后剩余位置；不能只验证条数少就称少切口。
- 无锚轮次先靠原尾界倒排，再做全局无重叠调度；遇到邻段/片头/片尾限制时，整段可移动块必须连续排开，保持文字和5.2计算时长。如果放不下，按容量冲突处理，不能改速或跨人合并。
- 有锚轮次：首锚之前的组贴着首锚向前倒排，末锚之后的组连续向后接排。两锚之间不能消除的正余量最多集中为一个接缝；无锚可移动组不能分散放置。保留已确认首锚及本次获准例外。
- `validate_turn_continuity`在调度后和导出前检查：无锚轮次、首锚前和末锚后的可移动连续块不得有内部空隙；两相邻固定锚组之间不得留下多个碎片空隙。与全局无重叠检查同时通过才可导出。
- 例：上师一轮原时间01:09.440—02:29.040，俄语计时55.580秒、无红点。默认排为01:33.460—02:29.040，而不是01:09.440—02:05.020。后面的提问者“谢谢”仍独立轮次；不能因首尾相接而合并成同一说话人。
- 此默认值只适用于说话轮次模式；原间隙模式沿用自身区间定位规则。固定开场、反应或谢词若需要精准定位，应使用现有对应锚点或用户明确的边界要求，不凭空创造锚点。

## 用户版参数

文中的5.2音节/秒和90秒为默认值；计划的speed和max_duration_ms可按用户本次明确选择覆盖，并在报告中显示。extra_pause_ms目前只接受0；不能声称支持尚未实现的停顿配置。无重叠和文字保真是交付约束。
