
# 俄语合并字幕与手势锚点

本技能是第一阶段：**合并与时间对齐 → 核验SRT → 交付SRT和定位报告，到此结束**。红点代表段内手势的目标时刻，不是字幕固定起点。不套用旧上传流程的700字母下限、额外停顿、0.20秒间隔、锚点审核写入或默认XLSX交付。

本包已拆为两个独立入口。本技能仅执行无交替口译、说话轮次模式。

## 与上传阶段的边界

- 本包的间隙/轮次入口已明确选择模式，另一模式的规则仅用于解释差异，不可在本次任务混用。源码中90秒是默认值，明确覆盖时使用max_duration_ms并在报告披露。

本阶段不需要HeyGen导出Excel，不生成HeyGen上传CSV/XLSX，也不自动调用上传转换技能。定位报告可含“锚点定位.csv”，它只是报告，不能冒充上传字幕。
- 用户检查SRT并按自己的流程处理视频、上传HeyGen、下载对应Excel后，再使用[heygen-ru-upload-csv](workflow.md)，提供该Excel和最终确认的合并双语SRT。
- 交付时记录来源版本、SRT摘要和未解决冲突，供第二阶段核对。用户后来修改了SRT，以其指定的最新版本为准，不能自动回退到本次旧稿。
- 单独要求制作上传CSV时，按第二阶段入口处理；缺少对应Excel只报告缺项，不能回退到旧的“SRT直接生成最终上传CSV”流程。

## 来源和范围

- 核实当前项目完整路径、序列UID/名称、帧率、最新字幕及红点。按本包premiere-connection.md进行只读连接；已保存工程可一次提取，记录摘要和未保存状态核查范围。桥梁拒绝时不修改保护，已获文件读取权限可用已保存文件；不得声称读到了未保存编辑。连接准备不保存、关闭或重启PR。
- 留存只读来源快照和提取记录，输出到新目录，不覆盖主工程、原字幕或旧交付。字幕及锚点编辑、视频剪辑、上传生成均不在本流程内。
- **先确认有俄文再计算。** 只有中文时先查找对应译文，按中文和cue顺序核实映射，不能直接套剪辑前时间。确实缺失时一次询问译文路径或是否先翻译；同时完成不依赖译文的锚点整理。只有授权翻译后，才另行执行用户明确要求的翻译任务；本包不含术语库或翻译技能。
- 优先批量提取/计算，仅检查锚点附近及异常段；缓存以来源摘要、序列、媒体映射区分。不每步重读全片，不让用户反复回复“继续”。真正的缺失信息才询问。

## 合并与保真

### 说话人边界是硬边界

- **换人边界优先于完整俄语句意、90秒、手势锚点和减少切口。** 主持人的介绍/欢迎与下一位的致辞不能因为译文连成一句就合并。也不能仅凭“欢迎、谢谢、下面有请”猜换人位置；核对交接前后实际声音，或能关联台词与讲话者的画面。镜头切到听众不等于换人，Excel不同标签也不单独证明真实换人。
- 在合并前建立源cue级说话轮次归属；每个交接点记录前后cue、可定位的音视频/用户确认证据、译文是否可在该cue边界分开。两种模式均使用`../scripts/speaker_guard.py`核验，格式见[说话轮次规则](speaker-mode.md)。不能从已经合并的分组反推归属表来“证明”分组正确，不能批量伪填confirmed或把机器检测写成实际听审。
- 不确定短句保留原文、独立列为待核查，不并入任何人的长段。单个cue已包含两个人、或翻译跨人连接导致无法按整cue正确分离时，停止相关合并交付，报告原cue及中俄原文；不擅自拆字、删句或改译文。先完成可以独立完成的核查，不重复要求用户确认已知事项。
- 程序只能检查归属记录、证据字段和分组是否一致，不能证明声音判断真实。缺失/过期记录、未确认归属、跨轮次合并或未解决跨人译句不得通过SRT导出检查；旧计划须重新核查后补录，不能自动迁移成“已确认”。

1. 原间隙模式：原相邻cue有任何正间隙（>0，即使1ms）就是不可跨越的合并边界；连续区间内按完整句意、说话人和自然段落合并。无交替口译模式改按说话轮次划界，不因正间隙自动拆大段。源重叠两种模式都单独报告，不默认为连续。
2. 每组同时满足原起止跨度≤90秒、计算并舍入后的发音时长≤90秒。90秒是上限，不凑满，不设最低时长。只有原间隙模式可为多个锚点额外拆组；少切口模式不为同组次锚额外拆组。
3. 只分配整条cue，每条恰好出现一次。单cue超过90秒、或理想拆点位于cue内部时报告限制，不暗中拆字、改译文或加速。已获用户明确授权拆cue时另记精确文字映射。
4. 中俄文字、标点及原顺序保留，只将原换行替为空格并以空格连接cue。不新增括号、注释、解释、标题、标点，不因估算而删除已有括号。中文栏的拉丁文字不误判为俄文。真实重复保留，可疑重复报告。

### 不漏句、不改句的交付条件

- 将本次读取的原始中俄字幕及编号、顺序留作独立核对基准；分组和计时计划从此基准引用文字，不手工重抄、润色、纠错或重译。音节计算中的读法展开不得写回字幕正文。
- 合并后按来源编号检查：每条原字幕恰好使用一次、顺序一致，无遗漏、重复加入或跳过。不得删除原文中本来就有的重复句。
- 按每组来源编号，从原始基准重新拼接中文和俄文，与导出后回读的SRT正文逐字符比较。唯一允许的正文格式变化是原换行转普通空格、相邻cue间加入一个连接空格；其余文字、数字、大小写、标点及已有空格必须一致。不能只把输出与计算计划自比来代替来源核对。
- 导出的SRT须为每条俄文一行、中文一行；若不符，报告异常并修正导出结构，不用“最后一行是中文”猜测来掩盖流程错误。
- 任一来源句缺失、重复加入或正文不一致时，不交付为完成稿；列出来源编号和具体差异，修复并重新核验。此核验是完成条件，不以“语义差不多”放行。

## 计时和手势对齐

固定使用默认的 **5.2音节/秒，不另加停顿或组间间隔**；用户以后明确改参数则记录该次覆盖。不沿用旧技能的额外停顿预算。无交替口译模式按`speaker-mode.md`调度；以下连续区间闭缝、多锚拆组与折中起点规则仅用于原间隙模式，执行前读[计算与定位规则](alignment.md)。

- 俄语元音计音节；数字、年份、拉丁词和缩写按语境在计算副本展开，保留输出原文。不确定读法不得按零处理。`две тысячи двадцать шесть`是7音节。
- **同一原始连续区间拆出的多组必须首尾相接。** 因90秒上限、句意或多锚点拆组，不得在区间内部人为留下空隙：输出必须满足前组结束=后组开始，包括舍入后的毫秒/帧边界。原字幕有正间隙的不同区间不强行相接。
- 同一区间只有一组含锚点时，先确定该组的锚点对齐位置并保持不变；前面的无锚点组按各自计算时长从它的起点向前倒排，后面的组从它的终点连续接排。例如后段起点不变，前段的新终点=后段起点，前段新起点=新终点−原计算时长；前段整体平移，不能只拉长结束时间。多段同样逐段递推。
- 整个连续区间都没有锚点时，第一组默认从原首cue开始，其余组连续接排；必要时整个区间顺延以避开前一区间。每组仍保持5.2计得的时长，不为填满画面减速、加停顿或拉长时长。“无锚点默认原起点”不再独立应用于已有锚点区间内的每一小组。
- 有锚点时核对画面、中文含义和俄语对应片语。具体指人/数量动作按词或短语起点；持续手势优先按语义核心，真实观察到持续区间后才允许采用窗口。只凭红点或三张截图不能宣称完整动作时窗已测定。
- 红点时间原样保留，求合并组起点，使段内对应俄语预计读到该点。区分词的开始/结束、语义核心和整个短语；不能用中文词序代替俄语词序。
- 多锚点先尝试在自然cue边界拆组，每组一个锚点并检查90秒、内容完整和邻组容量。无法合理拆时，求一个共同起点：优先各点偏差≤1秒，允许≤2秒。不能满足时选择用户优先或最明确的主锚点，逐个报告未对齐点及手动替代起点。不得暗中提速、改红点或扩大容差。
- 多锚点分布在同一连续区间的不同组时，仍须联合检查“组间零间隙”和各锚点偏差，不能把拆组当成允许独立平移并留空的理由。无法兼顾时报告连续排布与锚点的冲突；主锚取舍须明确记录，其余偏差不得隐藏。回排导致负起点、跨区间重叠或超尾时，也要报告；不得擅自移动已确定的单锚点组、改时长或剪视频来消除冲突。
- 同时检查前后组重叠、负起点及视频尾界。不能为避重叠直接顺延已对齐组而不复算偏差；存在不可行约束时交冲突方案，不标成最终可用稿。
- `../scripts/gesture_timing.py`负责已审阅分组/词映射的确定性计算和保真导出，不负责理解手势或自动翻译。输入格式及限制见参考文档。先作语义决策，工具核验后再交付。

## 验证、交付

- 重新读取导出的SRT核验编号、全部cue一次归属、双语文本、本次模式的分组边界、90秒、时序、锚点偏差及边界。原间隙模式逐个核对同一区间内部的相邻输出段结束=开始，不能只查无重叠；内部有空隙或重叠不得标成通过。首锚优先模式保留各组定位，所有空隙/重叠及次锚偏差明确报告，不把用户允许保留冲突写成零间隙通过。记录主工程摘要对比，仅说明实际核验范围。
- 交付调整时间后的合并双语SRT（每条俄文一行、中文一行，逗号毫秒，UTF-8 BOM/CRLF）和独立的锚点/时长报告；不生成HeyGen上传CSV或XLSX，不擅自导入PR，不在SRT正文夹注释。报告包含SRT完整路径、SHA256及待人工处理项；有未解决冲突仍标核对稿。
- 报告包含来源版本、每组原cue范围、原时段、新起止、音节数、各红点原时刻及对应中俄片语、预计发音时刻、正负偏差、主次锚点、词级/语义级及证据状态。冲突另列可替代起点/移动量/受影响组；秒和PR帧时码均按当前帧率报告。
- 5.2是规划模型，不是HeyGen逐词实际时间保证。区分机器识别、画面抽样、实际听审、生成后测量。数字可以精算，但不能把估算称作精确口型同步。没有生成音频时明确“预计”；有生成音频时用实际俄语词时刻复核，不能只优化数学误差。
